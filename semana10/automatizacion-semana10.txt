Diseño de flujo de automatización con n8n y Telegram

--- Descripción del flujo ---

Evento que activa el flujo:
Un ciudadano envía una petición POST a la ruta /reportes de la API comunitaria con
un nuevo reporte. El servidor registra el dato en el sistema y simultáneamente
dispara un webhook hacia n8n.

Flujo en n8n:
1. Nodo Webhook: recibe la notificación del servidor cuando se registra un nuevo reporte.
2. Nodo Función: extrae únicamente el tipo de incidencia y el id del reporte,
   descartando cualquier dato que pueda identificar al ciudadano.
3. Nodo Telegram: envía el mensaje de alerta al grupo o canal de coordinación.

Mensaje que se enviaría a Telegram:
"🔔 Nuevo reporte recibido.
Tipo: Infraestructura
ID: 7
Revisar el sistema para hacer seguimiento."

¿Qué información NO debe enviarse por seguridad?

- Nombres completos del ciudadano que reporta.
- Número de documento de identidad.
- Dirección exacta de residencia.
- Número de teléfono o correo electrónico.
- Tokens de API o claves de acceso al sistema.
- Contraseñas o credenciales de cualquier tipo.
- Datos de menores de edad.

El principio es enviar solo lo necesario para activar la revisión: el tipo de incidencia
y un identificador anónimo. Toda información sensible debe permanecer en el servidor
protegido, no en canales de mensajería.
